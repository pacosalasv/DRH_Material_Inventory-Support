## Read this first

Planned. Nothing to install, no release date. If you need material auditing today, the released tool below already does the single-scene case.

## The idea

Material Inventory is meant to work across a library instead of inside one file: which materials exist where, which ones duplicate each other, and which assets depend on a texture that has gone missing.

The scope is genuinely open. It could be an inventory, a duplicate finder, or a dependency checker, and I haven't decided which of those is the actual job.

## What exists today

[Scene Material Inventory](https://github.com/pacosalasv/DRH_Scene_Material_Inventory-Support) is released and free. It reports materials, shader nodes, images, PBR maps, and per-collection usage for the scene you have open, exporting HTML, XLSX, or CSV with path sanitization on by default.

If your problem is "what's in this file before I send it," that tool solves it now. If your problem is "what's in my whole folder of files," that's the gap this repo is about.

[Open an issue](https://github.com/pacosalasv/DRH_Material_Inventory-Support/issues) and describe the library: how many .blends, which texture layout, what goes wrong. Real folder structures decide scope better than feature lists.
